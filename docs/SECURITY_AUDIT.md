### Изменение поверхности атаки: симуляция потока и расписание (26.09.2026)

- **Новые эндпоинты:** `GET /api/sim/state` (любой вошедший), `POST /api/sim/start`, `POST /api/sim/stop` (engineer, admin). Все три закрыты входом — проверено тем же `test_every_non_public_endpoint_requires_login` (теперь 31 закрытая операция); `manager` и `dispatcher` получают 403 на запуск и остановку (`test_manager_is_read_only_everywhere`, `test_dispatcher_cannot_load_data_or_broadcast`).
- **Параметры:** `day` — дата (Pydantic), сутки без прогнозов — 422; `speed` 1–600 (422 вне диапазона, плюс CHECK в БД). Одна симуляция за раз — условный UPDATE в БД (409), гонка двух запусков невозможна и при нескольких процессах.
- **Аудит:** `sim_start` (сутки, скорость), `sim_stop` (сутки, модельное время) в `audit_log`; события скрипта — как обычный `ingest_events`.
- **Влияние на других пользователей:** активная симуляция меняет «Сейчас» для всех. Риск — путаница, не утечка: будущие исходы скрыты, «машина времени» по-прежнему доступна. В production по умолчанию выключено (`SIM_ENABLED=false` → запуск 403), кнопка в интерфейсе скрыта.
- **SSE:** новое служебное событие `sim_clock` без персональных данных (дата, скорость, модельное время).
- **Планировщик:** фоновые задания в процессе API (такт симуляции, разметка исходов) работают от имени сервиса, без внешнего входа; разметка исходов только добавляет строки `prediction_outcomes` (`ON CONFLICT DO NOTHING`) и ничего не удаляет. Ошибки заданий логируются и не роняют API.
- **Скрипт `simulate_stream`:** ходит в API по обычному JWT; `--purge-day` удаляет события одних суток и требует явного `--yes`, перед удалением сохраняет их копию в CSV. Прямой доступ к БД у скрипта — только внутри контейнера API (или с машины разработчика в demo).
- **Зависимость:** `apscheduler==3.11.3` (известных уязвимостей нет по данным pip-audit на 26.09.2026).
