# Срез реальных данных для экспертов

По умолчанию пакет запускается на **синтетическом демо** (`docker compose up --build`): так сервис можно проверить
без данных заказчика. Чтобы эксперты увидели **реальные прогнозы модели v3 и их исходы** (соответствие прогнозов
реальности — главный критерий оценки), команда передаёт отдельный архив среза. Он не лежит в репозитории: это
обезличенные данные заказчика, архив раздаётся по ссылке команды.

## Что в срезе

`expert_slice_20260601_20260630.zip` — июнь 2026 (последний месяц журнала заказчика), ≈ 137 МБ:

| Таблица | Строк | Зачем |
|---|---|---|
| `objects`, `channels` | 95, 11 485 | дерево объектов и справочник каналов целиком |
| `predictions` + `prediction_outcomes` | 5,4 млн + исходы | почасовые прогнозы `lgbm-2026.09-v3` за июнь и что случилось за 24 ч после каждого |
| `events_recent` | 5,1 млн | события июня: карточка датчика, журнал событий, симуляция суток |
| `channel_faults` | ≈ 106 тыс. | отказы по разметке с 03.03 (история для рекомендаций ТО — 90 дней) |
| `channel_daily` | ≈ 101 тыс. | суточные агрегаты с 02.05 (графики на карточке) |
| `model_metrics`, `model_thresholds` | 65, 40 | метрики теста 2026 v3 и v2, таблица порогов — экран «Качество модели» |
| `reasons`, `recommendations` | 14, 34 | справочники причин и рекомендаций |

В срезе **нет**: пользователей и паролей, журнала действий (`audit_log`), решений диспетчеров и заявок (реальных
решений у заказчика нет), тестовой базы `collector_test`. Точное число строк и контрольные суммы — в `manifest.json`
внутри архива.

## Загрузка (одна команда после запуска)

```bash
docker compose up -d --build                                   # как обычно — поднимется синтетическое демо
docker compose cp expert_slice_20260601_20260630.zip api:/tmp/slice.zip
docker compose exec api python -m scripts.load_expert_slice /tmp/slice.zip
docker compose restart api                                     # сбросить кэш агрегатов
```

Загрузка занимает ≈ 14 минут (5,4 млн прогнозов, 5,3 млн исходов и 5,1 млн событий с индексами; проверено на
чистой копии пакета). В Git Bash под Windows перед командами с путём `/tmp/…` задайте `export MSYS_NO_PATHCONV=1`,
иначе Git Bash подменит путь внутри контейнера на путь Windows; в PowerShell и Linux это не нужно.

Загрузчик проверяет формат, версию схемы БД и контрольные суммы, затем **в одной транзакции** заменяет демо-данные
срезом (при ошибке остаются прежние данные). Пользователи и их роли сохраняются; демо-пользователям заново
назначаются области по дереву реальных объектов (техник — «объект Альфа»). В production (`APP_ENV=production`)
загрузчик без `--force` не работает. Если в базе уже есть рабочие данные не демо-пользователей (решения, заявки,
области видимости), загрузчик печатает, что удалится, и тоже требует `--force` — сначала сделайте резервную копию.
Состав `manifest.json` сверяется с белым списком таблиц и колонок в коде (чужой SQL из архива не выполняется),
загрузка записывается в журнал действий (`expert_slice_load`). Подлинность архива — по `SHA256SUMS.txt`, который
команда раздаёт вместе со ссылкой.

## Как проверить

1. Войти «Диспетчером ОДС» (`ods` / `ods123`). В шапке «Машина времени» — `29.06.2026 23:00` (или кнопка «Сейчас»:
   экраны берут последний срез прогнозов 30.06 23:00).
2. «Качество модели» — версия `lgbm-2026.09-v3`, тест 2026: Precision 0,696, Recall 0,571; «прогноз против факта»
   по дням июня.
3. «Журнал» → «Прогнозы»: у прогнозов старше суток — исход «Сбылся / Не сбылся» (реальный отказ по журналу заказчика).
4. «Схема объектов» → «Схема коллектора»: 16 комплексов, датчики по пикетам.
5. Симуляция (инженер или ОДС): любые сутки июня, например 15.06.2026, ×600.

Вернуть синтетическое демо: `docker compose exec api python -m app.seed --force`.

## Как собран

Из основной базы команды (`DATABASE_URL` — основная база; с хоста Windows — `127.0.0.1`, не `localhost`):

```bash
cd backend
python -m scripts.build_expert_slice --from 2026-06-01 --to 2026-06-30 --out ../dist
```

Каждая таблица — `COPY … TO STDOUT` в CSV со сжатием gzip; состав и условия отбора — `backend/scripts/expert_slice.py`.
`dist/` — вне git.
